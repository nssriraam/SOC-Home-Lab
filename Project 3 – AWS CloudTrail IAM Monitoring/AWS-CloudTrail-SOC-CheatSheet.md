# ☁️ AWS CloudTrail – Cloud SOC Cheat Sheet

A concise **SOC analyst cheat sheet** for quickly investigating AWS CloudTrail events and distinguishing **normal cloud activity** from **security-relevant behavior**.

---

## 🔹 1️⃣ Where to Look (MOST IMPORTANT)

* **Service:** AWS CloudTrail
* **Section:** Event history
* **Purpose:** View audit logs for AWS account activity

🧠 **Mental model:**
**CloudTrail = `journalctl` for AWS**

---

## 🔹 2️⃣ Most Useful Filters (SOC Essentials)

### 🔸 Filter by User

* **User name:** `test-user`
* Used to track actions performed by a specific IAM user

---

### 🔸 Filter by Event Source

Common event sources:

* `signin.amazonaws.com`
* `sts.amazonaws.com`
* `s3.amazonaws.com`
* `iam.amazonaws.com`

✔️ Helps identify **which AWS service** generated the event

---

### 🔸 Filter by Error Code

Key error codes:

* `AccessDenied`
* `UnauthorizedOperation`

✔️ Used to detect **failed or unauthorized actions**

---

## 🔹 3️⃣ Common Cloud SOC Event Types (REMEMBER THESE)

| Event Type         | Meaning                                      |
| ------------------ | -------------------------------------------- |
| `ConsoleLogin`     | Human login attempt                          |
| `AssumeRole`       | Role-based authentication (human or service) |
| `AccessDenied`     | Authorization failure                        |
| `CreateUser`       | IAM user creation                            |
| `AttachRolePolicy` | Privilege change                             |
| `DeleteTrail`      | High-risk activity                           |

---

## 🔹 4️⃣ How to Read ONE Event (SOC Method)

When reviewing a CloudTrail event, always verify:

* **`userIdentity`** → Who performed the action
* **`eventSource`** → Which AWS service
* **`eventName`** → What action occurred
* **`errorCode`** → Success or failure
* **`sourceIPAddress`** → Origin of the request
* **`eventTime`** → Timestamp

✅ If you can answer these, you understand the event.

---

## 🔹 5️⃣ How to Decide: Alert or Ignore

### ✅ Usually NORMAL

* `AssumeRole` events generated by AWS services
* Single `AccessDenied` from a new or low-privileged user
* Setup-related management events

---

### 🚨 Potentially SUSPICIOUS

* Repeated `AccessDenied` events
* Unexpected role assumptions
* IAM privilege changes
* Login attempts from unusual IPs or locations

---

## 🔹 6️⃣ IAM Mental Model (VERY IMPORTANT)

* **Root user** → Account owner (high risk)
* **IAM user** → Individual human identity
* **IAM role** → Temporary access (used by users or services)
* **STS** → Issues temporary credentials

🧠 **Key insight:**
Most cloud activity is performed using **roles**, not humans.

---

## ✅ SOC Use Case

This reference helps SOC analysts to:

* Quickly triage CloudTrail events
* Reduce false positives from normal cloud noise
* Identify unauthorized or risky IAM activity
* Make accurate alerting decisions
